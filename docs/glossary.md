# מילון מונחים ותהליך העבודה

הקובץ הזה נכתב בשבילך, לא בשביל Claude. הוא מסביר בעברית פשוטה איך
העבודה במאגר הזה זורמת, ומה משמעות המונחים שחוזרים בכל סשן.

אין צורך לקרוא הכול ברצף — זה קובץ שחוזרים אליו כשמונח לא ברור.

---

## חלק א׳ — איך זורמת עבודה כאן

### התמונה בגדול

יש עותק אחד "רשמי" של הקוד, וכל שינוי עובר מסלול קבוע לפניו שהוא נכנס:

```
ענף חדש  →  קומיטים  →  דחיפה לשרת  →  בקשת מיזוג  →  תצוגה מקדימה
                                                            ↓
                                              אתה בודק בדפדפן
                                                            ↓
                                           מיזוג ל-main  →  עולה לאוויר
```

### למה בכלל מסלול, ולא פשוט לערוך?

כי `main` — הענף הרשמי — הוא מה שהמבקרים באתר רואים ומה שמותקן אצלכם
בטלפון כאפליקציה. שינוי שנכנס לשם ישר, נכנס גם אם הוא שבור. המסלול
קונה שני דברים: מקום לעבוד בו בלי סיכון, ורגע אחד שבו בן אדם מסתכל
לפני שזה מגיע לקהל.

### חמשת השלבים, אחד־אחד

**1. ענף (branch).** עותק פרטי של הקוד שנפרד מ-`main` לצורך משימה אחת.
מה שקורה בו לא נוגע לאתר החי. לכל משימה ענף משלה, ושמו מתאר את המשימה.

**2. קומיט (commit).** נקודת שמירה. אוסף שינויים שנשמר יחד עם הודעה
שמסבירה *למה* השינוי נעשה. אפשר תמיד לחזור לנקודה קודמת, ואפשר לקרוא
את היסטוריית ההודעות כדי להבין למה משהו נראה כמו שהוא נראה.

**3. דחיפה (push).** העלאת הקומיטים מהמחשב שעליו עובדים אל GitHub, כדי
שגם אתה תוכל לראות אותם ושהם לא ילכו לאיבוד.

**4. בקשת מיזוג (Pull Request, בקיצור PR).** הבקשה הרשמית לצרף את הענף
אל `main`. ה-PR הוא גם דף הדיון — רואים בו בדיוק אילו שורות השתנו,
אפשר להעיר, ואפשר לדחות. `draft` (טיוטה) פירושו "עוד לא בשל למיזוג".

**5. מיזוג (merge).** אישור ה-PR. השינויים נכנסים ל-`main`, ומשם עולים
לאוויר תוך דקות.

### איפה אתה נכנס לתמונה — התצוגה המקדימה

ברגע שנפתח PR, Netlify בונה ממנו אתר חי וזמני בכתובת ייעודית:

```
https://deploy-preview-<מספר ה-PR>--singular-biscotti-c916b6.netlify.app/app/
```

זו הסביבה הכי קרובה לייצור, והבדיקה הזו היא **שלך** — סביבת הסוכן חסומה
מהכתובת הזו, כך ש-Claude פיזית לא יכול לפתוח אותה. כשאתה מקבל קישור
כזה, זה הרגע להסתכל בטלפון.

שים לב להבדל: **התצוגה המקדימה** נבנית ב-Netlify לכל PR בנפרד; **הייצור**
(`ganpereh.co.il`) מוגש מ-GitHub Pages ומתעדכן רק אחרי מיזוג ל-`main`.

### עבודה בענפים מקבילים

שתי משימות שלא נוגעות באותם קבצים יכולות לרוץ בו־זמנית, כל אחת בענף
משלה ובסשן משלה. זה חוסך זמן אמיתי. הסייג היחיד: אם שתיהן עורכות את
אותו קובץ, המיזוג השני ייתקל ב**קונפליקט** — גיט לא יודע איזו גרסה
נכונה ומבקש הכרעה ידנית. לכן ההצעה לפיצול תמיד באה עם הסבר אילו קבצים
כל צד נוגע בהם.

## חלק ב׳ — מילון

### גיט ו-GitHub

| מונח | מה זה |
|---|---|
| **מאגר** (repository, repo) | התיקייה של הפרויקט על כל ההיסטוריה שלה. כאן: `ganpereh-site`. |
| **ענף** (branch) | קו פיתוח נפרד. `main` הוא הרשמי, השאר זמניים. |
| **קומיט** (commit) | נקודת שמירה עם הודעת הסבר. |
| **push / pull** | דחיפה של שינויים ל-GitHub / משיכה של שינויים ממנו. |
| **PR** (Pull Request) | בקשה לצרף ענף ל-`main`, ודף הדיון עליה. |
| **diff** | תצוגת ההבדלים — מה נמחק ומה נוסף, שורה־שורה. |
| **קונפליקט** (conflict) | שני ענפים שינו את אותה שורה. דורש הכרעה ידנית. |
| **rollback / revert** | חזרה לגרסה קודמת. אפשרי תמיד, וזו כל הנקודה בקומיטים. |

### רשת ואינטרנט

| מונח | מה זה |
|---|---|
| **HTML** | השלד — מה יש בעמוד: כותרת, פסקה, תמונה, כפתור. |
| **CSS** | העיצוב — צבע, גודל, מרווח, פריסה. |
| **JavaScript** (JS) | ההתנהגות — מה קורה בלחיצה, איפה נשמרים הנתונים. |
| **DOM** | ייצוג העמוד בזיכרון הדפדפן. JS משנה את ה-DOM, והמסך משתנה בעקבותיו. |
| **סלקטור** (selector) | כתובת של אלמנט בעמוד, למשל `#screen-list`. הבסיס גם ל-CSS וגם לבדיקות. |
| **RTL** | ימין־לשמאל. עברית מחייבת היפוך של פריסה, לא רק של טקסט. |
| **מובייל־תחילה** | מעצבים למסך הטלפון קודם, ומרחיבים למסכים גדולים. מסך הייחוס כאן: 390×844 פיקסלים. |
| **סטטי** (static site) | אתר של קבצים מוכנים בלבד, בלי שרת שמחשב תשובות. מהיר, זול, וכמעט בלתי אפשרי לפרוץ. |

### האפליקציה

| מונח | מה זה |
|---|---|
| **PWA** | אתר שאפשר להתקין כאפליקציה במסך הבית ולהריץ בלי אינטרנט. |
| **service worker** | הרכיב שמחזיק עותק של האפליקציה במכשיר. הוא הסיבה שהיא עובדת אופליין — וגם הסיבה שגרסה ישנה נתקעת אם שוכחים להעלות `VERSION`. |
| **מטמון** (cache) | העותק המקומי הזה. "לנקות מטמון" = לזרוק אותו ולמשוך מחדש. |
| **localStorage** | מחסן קטן בדפדפן שבו נשמרים הנתונים שלכם. יושב **במכשיר בלבד** — לא בענן, ולא עובר בין מכשירים. |
| **ES modules** | שיטה לפצל JS לקבצים שמייבאים זה מזה, בלי כלים נוספים. |
| **build / תלויות** | שלב הידור וספריות חיצוניות. כאן **אין** אף אחד מהם, בכוונה — מה שכתוב הוא מה שרץ. |

### בדיקה ואיכות

| מונח | מה זה |
|---|---|
| **בדיקות אוטומטיות** (tests) | קוד שבודק קוד. `app/dev/tests.html` מריץ 207 בדיקות ומראה ירוק/אדום. |
| **רגרסיה** (regression) | משהו שעבד ונשבר בעקבות שינוי אחר. זה מה שהבדיקות נועדו לתפוס. |
| **Playwright / Chromium** | הפעלת דפדפן אמיתי בלי חלון, לצילומי מסך ולבדיקות מלאות. |
| **פרמוט** (prettier) | סידור אוטומטי של רווחים ושורות. אחידות בלבד, אפס שינוי בהתנהגות. |
| **שרת סטטי מקומי** | `python3 -m http.server` — מגיש את הקבצים למחשב עצמו, כדי לבדוק לפני העלאה. |
